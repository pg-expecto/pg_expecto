# test.sh — управление нагрузочным тестированием

Скрипт предназначен для автоматического управления нагрузочным тестированием.  
Он проверяет количество инцидентов в БД за текущие сутки и в зависимости от целевого значения запускает или останавливает нагрузочный тест.

Скрипт рассчитан на запуск по `cron` каждый час.

---

## Назначение

Скрипт выполняет следующие функции:

- принимает целевое количество инцидентов в сутки;
- считает фактическое количество инцидентов за текущий день;
- запускает нагрузочный тест, если целевое значение ещё не достигнуто;
- останавливает нагрузочный тест, если целевое значение достигнуто;
- использует флаг-файл, чтобы не запускать и не останавливать тест повторно.

---

## Требования

- Bash
- Доступ к PostgreSQL через `psql`
- Наличие таблицы `performance_incident` с полем `start_timepoint`
- Исполняемые скрипты:
  - `/postgres/pg_expecto/sh/load_test/load_test_start.sh`
  - `/postgres/pg_expecto/sh/load_test/load_test_stop.sh`
- Права на создание и удаление флаг-файла:
  - `/postgres/pg_expecto/sh/load_test/LOAD_TEST_IN_PROGRESS`
- Настроенный доступ к БД:
  - база: `expecto_db`
  - пользователь: `expecto_user`

---

## Параметры запуска

```bash
./test.sh <target_incidents>
```

| Параметр | Обязательный | Описание |
|---|---:|---|
| `target_incidents` | Да | Целевое количество инцидентов в сутки. Целое число больше `0`. |

Пример:

```bash
/postgres/pg_expecto/sh/prod_test.sh 1000
```

---

## Пример запуска через cron

```cron
0 * * * * /postgres/pg_expecto/sh/prod_test.sh <target_incidents> >> /postgres/pg_expecto/sh/prod_test.sh.log 2>&1
```

Пример с конкретным значением:

```cron
0 * * * * /postgres/pg_expecto/sh/prod_test.sh 1000 >> /postgres/pg_expecto/sh/prod_test.sh.log 2>&1
```

## Настраиваемые переменные

В скрипте заданы следующие переменные:

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `STOP_SCRIPT` | `/postgres/pg_expecto/sh/load_test/load_test_stop.sh` | Скрипт остановки нагрузочного теста |
| `START_SCRIPT` | `/postgres/pg_expecto/sh/load_test/load_test_start.sh` | Скрипт запуска нагрузочного теста |
| `DB_NAME` | `expecto_db` | Имя базы данных |
| `DB_USER` | `expecto_user` | Пользователь БД |
| `FLAG_FILE` | `/postgres/pg_expecto/sh/load_test/LOAD_TEST_IN_PROGRESS` | Флаг-файл, обозначающий, что тест запущен |

При необходимости измените пути и параметры подключения под своё окружение.

---

## Алгоритм работы

1. Проверяется наличие и корректность входного параметра.
2. Выполняется SQL-запрос к таблице `performance_incident`:

   ```sql
   SELECT COUNT(*)
   FROM performance_incident
   WHERE start_timepoint >= date_trunc('day', now())
     AND start_timepoint < date_trunc('day', now()) + interval '1 day';
   ```

3. Полученное количество сравнивается с целевым значением.

### Если количество инцидентов больше или равно целевому

- Если флаг-файл существует:
  - считается, что нагрузочный тест запущен;
  - вызывается скрипт остановки `load_test_stop.sh`.
- Если флаг-файла нет:
  - считается, что тест не запущен;
  - скрипт завершается без действий.

### Если количество инцидентов меньше целевого

- Если флаг-файл существует:
  - считается, что тест уже запущен;
  - скрипт завершается без действий.
- Если флаг-файла нет:
  - вызывается скрипт запуска `load_test_start.sh`.

---

## Коды возврата

| Код | Описание |
|---:|---|
| `0` | Успешное выполнение. Действия либо выполнены, либо не требуются. |
| `1` | Ошибка: неверные аргументы, не удалось получить количество записей, отсутствует или не исполняем нужный скрипт запуска/остановки. |

## Логирование

Скрипт выводит в `stdout` информацию о:

- текущем количестве инцидентов;
- целевом количестве;
- факте достижения цели;
- состоянии нагрузочного теста;
- выполняемых действиях.

При запуске через `cron` рекомендуется перенаправлять вывод в лог-файл:

```bash
>> /postgres/pg_expecto/sh/prod_test.sh.log 2>&1
```

## Установка

1. Разместите скрипт в каталоге, например:

   ```bash
   /postgres/pg_expecto/sh/prod_test.sh
   ```

2. Сделайте его исполняемым:

   ```bash
   chmod +x /postgres/pg_expecto/sh/prod_test.sh
   ```

3. Убедитесь, что скрипты запуска и остановки существуют и исполняемы:

   ```bash
   chmod +x /postgres/pg_expecto/sh/load_test/load_test_start.sh
   chmod +x /postgres/pg_expecto/sh/load_test/load_test_stop.sh
   ```

4. Настройте доступ к PostgreSQL для пользователя, от которого работает `cron`.

5. Добавьте задание в `cron`:

   ```cron
   * * * * * /postgres/pg_expecto/sh/prod_test.sh 1000 >> /postgres/pg_expecto/sh/prod_test.sh.log 2>&1
   ```

---

## Примечания и ограничения

- Скрипт считает инциденты за текущие календарные сутки, а не за последние 24 часа.
- Проверка состояния теста выполняется только по наличию флаг-файла, его содержимое не анализируется.
- Скрипт не использует блокировки. При одновременном запуске нескольких копий возможна гонка.
- Ошибки `psql` подавляются через `2>/dev/null`, после чего выполняется проверка полученного значения.
- Пути к скриптам и БД заданы в коде и требуют ручной настройки под конкретное окружение.
- Для неинтерактивного подключения к PostgreSQL рекомендуется использовать `.pgpass` или переменные окружения `PGPASSWORD`, `PGUSER` и т.п.
