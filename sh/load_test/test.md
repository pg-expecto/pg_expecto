# test.sh — управление нагрузочным тестированием (v3.1)

Скрипт автоматически управляет нагрузочным тестированием с учётом
**продуктивного периода** и **режимов нагрузки** (`LOW` / `HIGH`).

Он проверяет количество инцидентов в БД за текущие сутки, определяет,
находится ли текущий момент в продуктивном периоде (по данным таблицы
`markov_config`), и в зависимости от этого:

- переключает нагрузку между режимами `LOW` и `HIGH`;
- запускает или останавливает нагрузочный тест при достижении целевого
  количества инцидентов;
- использует флаг-файл, чтобы не выполнять повторные действия.

Скрипт рассчитан на запуск по `cron` **каждые 10 минут**.

---

## Назначение

Скрипт выполняет следующие функции:

- принимает целевое количество инцидентов в сутки (`target_incidents`);
- получает из `markov_config` границы продуктивного периода
  (`productive_load_start_hour`, `productive_load_end_hour`);
- в **непродуктивный** период держит нагрузку в режиме `LOW`;
- в **продуктивный** период:
  - переключает нагрузку в режим `HIGH`;
  - считает фактическое количество инцидентов за текущий день;
  - останавливает тест, если целевое значение достигнуто;
  - запускает тест, если целевое значение ещё не достигнуто;
- использует флаг-файл, чтобы не запускать и не останавливать тест
  повторно.

---

## Требования

- Bash
- Доступ к PostgreSQL через `psql`
- Наличие таблицы `performance_incident` с полем `start_timepoint`
- Наличие таблицы `markov_config` с полями:
  - `productive_load_start_hour` (0–23)
  - `productive_load_end_hour` (0–23, ≥ `productive_load_start_hour`)
- Исполняемые скрипты:
  - `/postgres/pg_expecto/sh/load_test/load_test_start.sh`
  - `/postgres/pg_expecto/sh/load_test/load_test_stop.sh`
- Файлы параметров нагрузки:
  - `/postgres/pg_expecto/sh/load_test/param.conf` — текущий активный
    профиль нагрузки (содержимое перезаписывается скриптом);
  - `/postgres/pg_expecto/sh/load_test/param.conf.low` — шаблон профиля
    `LOW`;
  - `/postgres/pg_expecto/sh/load_test/param.conf.high` — шаблон профиля
    `HIGH`.
- Права на создание/удаление флаг-файла:
  - `/postgres/pg_expecto/sh/load_test/LOAD_TEST_IN_PROGRESS`
- Настроенный доступ к БД:
  - база: `expecto_db`
  - пользователь: `expecto_user`

> **Определение режима.** Режим считается `LOW`, если `param.conf`
> содержит строку с `low`, и `HIGH`, если содержит строку с `high`.
> Шаблоны `param.conf.low` / `param.conf.high` должны этому
> соответствовать.

## Параметры запуска

```bash
./test.sh <target_incidents>
```

| Параметр | Обязательный | Описание |
|---|---:|---|
| `target_incidents` | Да | Целевое количество инцидентов в сутки. Целое число больше `0`. |

Пример:

```bash
/postgres/pg_expecto/sh/load_test/test.sh 4
```

## Пример запуска через cron

```cron

```

## Алгоритм работы

### 0. Инициализация и проверки

1. Проверяется наличие и корректность входного параметра
   `target_incidents` (целое положительное число).
2. Выполняется SQL-запрос к таблице `markov_config`:

   ```sql
   SELECT productive_load_start_hour, productive_load_end_hour
   FROM markov_config
   LIMIT 1;
   ```

3. Проверяется, что получены два числа в диапазоне `0..23`
   и `start_hour ≤ end_hour`.
4. Определяется текущий час `CURRENT_HOUR = date +%H`.
5. В зависимости от того, попадает ли текущий час в продуктивный
   период, скрипт переходит в одну из двух ветвей.

> **Продуктивный период** — интервал `[START_HOUR, END_HOUR]`
> **включительно**. Всё, что вне этого интервала, — **непродуктивный
> период**.

### 1. Непродуктивный период

Условие: `CURRENT_HOUR < START_HOUR` **или** `CURRENT_HOUR > END_HOUR`.

#### 1.1. Флаг-файл существует (тест уже запущен)

- Проверяется режим в `param.conf`.
- Если режим `LOW`:
  - ничего не делается, выход с кодом `0`.
- Если режим `HIGH`:
  1. вызывается `load_test_stop.sh`;
  2. выполняется `cp param.conf.low → param.conf`;
  3. вызывается `load_test_start.sh`;
  4. выход с кодом `0`.

#### 1.2. Флаг-файла нет (тест не запущен)

1. выполняется `cp param.conf.low → param.conf`;
2. вызывается `load_test_start.sh`;
3. выход с кодом `0`.

### 2. Продуктивный период

#### 2.1. Переключение в режим `HIGH`

Если в `param.conf` режим **не** `HIGH`:

1. вызывается `load_test_stop.sh`;
2. выполняется `cp param.conf.high → param.conf`;
3. вызывается `load_test_start.sh`;
4. выход с кодом `0`.

#### 2.2. Подсчёт инцидентов за сегодня

Если режим уже `HIGH`, выполняется SQL-запрос:

```sql
SELECT COUNT(*)
FROM performance_incident
WHERE start_timepoint >= date_trunc('day', now())
  AND start_timepoint < date_trunc('day', now()) + interval '1 day';
```

Полученное значение `COUNT` сравнивается с `TARGET_INCIDENTS`.

#### 2.3. `COUNT >= TARGET_INCIDENTS` (цель достигнута)

- Если флаг-файл существует:
  1. вызывается `load_test_stop.sh`;
  2. выход с кодом `0`.
- Если флаг-файла нет:
  - логируется, что тест не запущен;
  - выполняется `cp param.conf.high → param.conf`;
  - вызывается `load_test_start.sh`
    (сообщение в логе — «СТАРТ МИНИМАЛЬНОЙ НАГРУЗКИ»).

#### 2.4. `COUNT < TARGET_INCIDENTS` (цель не достигнута)

- Если флаг-файл существует:
  - ничего не делается, выход с кодом `0`.
- Если флаг-файла нет:
  1. выполняется `cp param.conf.high → param.conf`;
  2. вызывается `load_test_start.sh`;
  3. выход с кодом `0`.

## Сводная таблица поведения

| Период | Флаг | Режим в `param.conf` | Действие |
|---|---|---|---|
| Непродуктивный | есть | `LOW` | ничего |
| Непродуктивный | есть | `HIGH` | стоп → `LOW` → старт |
| Непродуктивный | нет | — | `LOW` → старт |
| Продуктивный | — | `LOW` | стоп → `HIGH` → старт |
| Продуктивный | есть | `HIGH` | стоп (цель достигнута) / ничего (цель не достигнута) |
| Продуктивный | нет | `HIGH` | `HIGH` → старт |

---

## Коды возврата

| Код | Описание |
|---:|---|
| `0` | Успешное выполнение. Действия либо выполнены, либо не требуются. |
| `1` | Ошибка: неверные аргументы, не удалось получить данные из БД (`markov_config` или `performance_incident`), некорректные продуктивные часы, отсутствует или не исполняем нужный скрипт запуска/остановки. |

## Логирование

Скрипт выводит в `stdout` (в формате
`TIMESTAMP : DD-MM-YYYY HH:MM:SS: <сообщение>`):

- тип текущего периода (`ПРОДУКТИВНЫЙ` / `НЕ ПРОДУКТИВНЫЙ`);
- текущий режим нагрузки;
- текущее и целевое количество инцидентов;
- факт достижения цели;
- состояние нагрузочного теста (запущен / не запущен);
- выполняемые действия (запуск, остановка, переключение режима).

При запуске через `cron` рекомендуется перенаправлять вывод в лог-файл:

```bash
>> /postgres/pg_expecto/sh/load_test/test.log 2>&1
```

## Установка

1. Разместите скрипт в каталоге:

   ```bash
   /postgres/pg_expecto/sh/load_test/test.sh
   ```

2. Сделайте его исполняемым:

   ```bash
   chmod +x /postgres/pg_expecto/sh/load_test/test.sh
   ```

3. Убедитесь, что скрипты запуска и остановки существуют и исполняемы:

   ```bash
   chmod +x /postgres/pg_expecto/sh/load_test/load_test_start.sh
   chmod +x /postgres/pg_expecto/sh/load_test/load_test_stop.sh
   ```

4. Подготовьте шаблоны параметров нагрузки:

   ```bash
   ls /postgres/pg_expecto/sh/load_test/param.conf.low
   ls /postgres/pg_expecto/sh/load_test/param.conf.high
   ```

   В каждом из файлов должна присутствовать строка, содержащая
   соответственно `low` или `high` — по ней скрипт определяет режим.

5. Настройте доступ к PostgreSQL для пользователя, от которого
   работает `cron`.

6. Добавьте задание в `cron`:

   ```cron
   */10 * * * * /postgres/pg_expecto/sh/load_test/test.sh 4 >> /postgres/pg_expecto/sh/load_test/test.log 2>&1
   ```

## Примечания и ограничения

- Скрипт считает инциденты за текущие календарные сутки, а не за
  последние 24 часа.
- Продуктивный период берётся из `markov_config` и трактуется как
  замкнутый интервал `[START_HOUR, END_HOUR]`. Если `START_HOUR ==
  END_HOUR`, продуктивным считается ровно один час.
- Переключение режима выполняется только при запуске скрипта, т.е.
  с точностью до интервала cron (по умолчанию — 10 минут).
- Режим определяется по наличию подстроки `low` / `high` в
  `param.conf`, а не по отдельной переменной. Убедитесь, что эти
  слова не встречаются в файле в иных контекстах.
- Скрипт не использует блокировки. При одновременном запуске
  нескольких копий возможна гонка (особенно при переключении режимов
  и `cp` в `param.conf`).
- Ошибки `psql` подавляются через `2>/dev/null`, после чего
  выполняется проверка полученного значения.
- Пути к скриптам, `param.conf` и параметры БД заданы в коде и
  требуют ручной настройки под конкретное окружение.
- Для неинтерактивного подключения к PostgreSQL рекомендуется
  использовать `.pgpass` или переменные окружения `PGPASSWORD`,
  `PGUSER` и т.п.
