## Обзор

Тестовый стенд предназначен для:

- генерации синтетической нагрузки (OLTP/OLAP) на тестовую БД PostgreSQL с Пуассоновским распределением;
- имитации заданного количества инцидентов производительности в сутки;
- сбора статистики по операционной скорости и ожиданиям СУБД;
- прогнозирования риска инцидентов производительности с помощью цепи Маркова.

## Компоненты

| Компонент | Назначение | Репозиторий |
|-----------|------------|-------------|

| `markov_chain` | Цепь Маркова для прогнозирования риска инцидентов производительности | [pg-expecto/markov_chain](https://github.com/pg-expecto/markov_chain) |

## Требования

- Установленный PostgreSQL с тестовой БД.
- Репозитории `pg_expecto` и `markov_chain`, размещённые в каталоге `/postgres/pg_expecto/`.
- Доступ к `cron` для запуска скриптов по расписанию.

## Шаг 1. Настройка нагрузочного тестирования

Перейдите в каталог настроек нагрузочного тестирования:

```bash
cd /postgres/pg_expecto/sh/load_test
vi param.conf
```

### Параметры `param.conf`

| Параметр | Описание | Пример |
|----------|----------|--------|
| `start_load` | Начальная нагрузка | `5` |
| `finish_load` | Максимальная нагрузка | `40` |
| `testdb` | Тестовая БД | `default` |
| `load_mode` | Тип синтетической нагрузки (`olap` / `oltp`) | `oltp` |
| `period_hours` | Длительность теста в часах; `-1` — бесконечный тест | `-1` |
| `average_load` | Средняя нагрузка | `20` |
| `scenario1` | Вес сценария 1 | `0.7` |
| `scenario2` | Вес сценария 2 | `0.2` |
| `scenario3` | Вес сценария 3 | `0.1` |
| `init_test_db` | Инициализировать тестовую БД (`on`/`off`) | `on` |
| `scale` | Размер тестовой БД (единицы масштабирования) | `685` (~10 ГБ) |

### Пример заполнения `param.conf`

```ini
# НАСТРОЙКИ НАГРУЗОЧНОГО ТЕСТИРОВАНИЯ
# Начальная нагрузка
start_load = 5
# Максимальная нагрузка
finish_load = 40
# Тестовая БД
testdb = default
# Тип синтетической нагрузки
#load_mode = olap
load_mode = oltp
# БЕСКОНЕЧНЫЙ ТЕСТ.
# ДЛЯ ОСТАНОВКИ
# /postgres/pg_expecto/sh/load_test/load_test_stop.sh
period_hours = -1
average_load = 20
# Веса сценариев по умолчанию
scenario1 = 0.7
scenario2 = 0.2
scenario3 = 0.1
# Инициализировать тестовую БД
init_test_db = on
# Размер тестовой БД
#scale = 20
#~10GB
scale = 685
```

> **Примечание.** Для бесконечного теста (`period_hours = -1`) остановка выполняется вручную скриптом `load_test_stop.sh` (см. [Остановка теста](#остановка-теста)).

## Шаг 2. Скрипт имитации нагрузки `test.sh`

Скрипт `test.sh` автоматически управляет нагрузочным тестированием:

1. Проверяет количество инцидентов в БД за текущие сутки.
2. Сравнивает его с целевым значением.
3. Запускает или останавливает нагрузочный тест в зависимости от результата.

Нагрузка генерируется с **Пуассоновским распределением** и заданным количеством инцидентов в сутки.

### Использование

```bash
/postgres/pg_expecto/sh/load_test/test.sh <ЦЕЛЕВОЕ_КОЛИЧЕСТВО_ИНЦИДЕНТОВ_В_СУТКИ>
```

Пример — цель **4 инцидента в сутки**:

```bash
/postgres/pg_expecto/sh/load_test/test.sh 4
```

## Шаг 3. Запуск по расписанию (cron)

Для регулярного запуска (проверка и корректировка нагрузки раз в час) добавьте задание в `cron`:

```cron
0 * * * * /postgres/pg_expecto/sh/load_test/test.sh 4 >> /postgres/pg_expecto/sh/load_test/test.log 2>&1
```

Журнал работы скрипта сохраняется в `/postgres/pg_expecto/sh/load_test/test.log`.

## Остановка теста

Для остановки бесконечного нагрузочного теста (`period_hours = -1`) выполните:

```bash

```
